# FLOWS.md — Карта экранов и состояний (этап 1, вывод UX-аналитика)

> Разовый артефакт по §7a TZ.md: 7 экранов × 6 состояний каждый + требования доступности.
> Визуальный язык — `DESIGN.md`. Это спецификация для этапа 8 (UI): каждый экран и каждое
> состояние ниже должно быть реализуемо напрямую из этого файла.

## Общие принципы для всех экранов

### 6 базовых состояний (для каждого экрана и сценария)

| Состояние | Что видит пользователь | Индикация |
|---|---|---|
| **Начало** | Экран в исходном виде до первого действия пользователя | Пустые/дефолтные данные, доступны primary-действия |
| **Успешный результат** | Операция завершилась, данные показаны | Чип `chip-success` «Готово» / обновлённые данные |
| **Пустое состояние** | Данных нет, но это не ошибка | Иллюстрация-заглушка (sunburst-декор + текст), подсказка первого действия, CTA-кнопка |
| **Ожидание** | Операция в процессе | Skeleton-плейсхолдеры вместо данных + текстовый статус («Идёт анализ, шаг 2 из 5…»), прогресс; статус читаем без цвета |
| **Ошибка** | Операция не удалась | Красная рамка/баннер с текстом ошибки (текстом, не только цветом), код/детали, кнопка «Повторить» |
| **Восстановление** | Пользователь вышел из ошибки или долгого ожидания | Возврат к последнему корректному виду; незавершённые данные не теряются; кнопка «Продолжить» если шаг восстановим |

### Доступность (обязательна на каждом экране)

- Все действия доступны с клавиатуры; порядок табуляции логичен.
- Видимый фокус: рамка `#1650C8` 2px (как фокус полей ввода).
- У каждого поля — подпись `<label>`; placeholder не заменяет подпись.
- Статус и состояние понятны без цвета: текст + иконка, не только красный/зелёный.
- На ширине 390px основные действия доступны без горизонтальной прокрутки.

## 1. Воронка (главная)

Список/доска идей: приоритеты, этапы воронки, фильтры, очередь, действия.

| Состояние | Поведение |
|---|---|
| Начало | Загружен список активных идей, фильтры по умолчанию (все этапы), кнопка «Новая идея» — primary |
| Успех | Создание/архивирование/смена приоритета → карточка обновляется в списке, чип «Готово» |
| Пусто | «Пока нет идей. Опишите первую — голосом или текстом» + CTA «Новая идея» |
| Ожидание | Skeleton-карточки при загрузке списка; у идеи в работе — текст статуса шага («Исследование, шаг 2 из 5…») |
| Ошибка | Баннер «Не удалось загрузить список» + «Повторить»; список остаётся с последними данными если они есть |
| Восстановление | После ошибки повторная загрузка; после завершения шага идеей статус в карточке обновляется сам при следующем опросе |

Сценарии: фильтрация по этапу/приоритету; архивирование освобождает слот; 11-я идея — баннер «Достигнут лимит 10 активных идей. Заархивируйте что-нибудь»; повторный клик «Поставить в очередь» не создаёт дубль.

## 2. Новая идея

Запись голоса / ввод текста → расшифровка → редактирование → сохранение.

| Состояние | Поведение |
|---|---|
| Начало | Переключатель «Голос / Текст» (сегменты, активный — `#E4EAFB` с синим текстом); поле текста или кнопка записи |
| Успех | Расшифровка появилась в поле — редактируемая; «Сохранить» → редирект на карточку |
| Пусто | Пустое поле/нет записи: «Сохранить» disabled; подсказка «Опишите идею в 2–3 предложениях» |
| Ожидание | Индикатор записи (таймер + волновая анимация); при расшифровке — «Расшифровываем…» skeleton в поле |
| Ошибка | Нет доступа к микрофону: текст «Доступ к микрофону не выдан. Разрешите доступ в настройках браузера или переключитесь на текст»; отклонённый доступ — то же; расшифровка не удалась: «Не удалось расшифровать, попробуйте ещё раз или введите текст» — введённый текст сохраняется |
| Восстановление | После ошибки записи → возврат к переключателю, можно переключиться на текст без потери набранного; неполная расшифровка — поле редактируемо, пользователь дописывает вручную |

Сценарии: длинные названия (>100 символов) — поле принимает, обрезка только в списке воронки с «…»; превышение лимита записи (10 мин) — запись останавливается с сообщением; голосовые данные помечены как источник в карточке.

## 3. Карточка идеи

Исходная идея, уточнения, история версий, запуск/пауза/продолжение.

| Состояние | Поведение |
|---|---|
| Начало | Открыта карточка: поля (title, source_transcript, structured_idea, problem, audience, value, priority, funnel_stage, execution_status), история версий свёрнута |
| Успех | Редактирование → «Сохранить» → новая версия, баннер «Создана версия N, зависимые выводы помечены устаревшими» |
| Пусто | Нет истории версий (v1): блок истории скрыт; нет результатов анализа: разделы отчёта — «Анализ ещё не запускался» + CTA «Запустить анализ» |
| Ожидание | Идея в работе: текст статуса + спиннер у execution_status=running; поля карточки заблокированы от правки на время шага |
| Ошибка | execution_status=error: баннер с текстом ошибки шага, кнопки «Повторить шаг» / «Пауза»; waiting_for_data: текст ожидания и что нужно сделать |
| Восстановление | «Продолжить» после паузы; после повторного анализа устаревшие метки снимаются; старые версии доступны в истории всегда |

Сценарии: изменение идеи после анализа → новая версия + устаревшие выводы (§3 TZ); запуск/пауза/продолжение — идемпотентно, повторный клик не создаёт дубль.

## 4. Ход работы

Какой агент занят, что завершено, почему остановка, что делать дальше.

| Состояние | Поведение |
|---|---|
| Начало | Список шагов пайплайна (по ролям §7): статус каждого (завершён / в работе / ждёт / ошибка) |
| Успех | Шаг завершён → галочка + время выполнения + краткий результат; последний шаг → «Анализ завершён, отчёт готов» + ссылка |
| Пусто | Анализ не запускался: «Запустите анализ, чтобы увидеть ход работы» + CTA |
| Ожидание | Активный шаг: имя роли, что делает («Аналитик рынка: ищет конкурентов…»), спиннер; пункт «Идёт шаг 3 из 5» |
| Ошибка | Остановившийся шаг: красный статус с текстом ошибки, «Почему остановка» — причина; кнопки «Повторить шаг» / «Пауза» |
| Восстановление | После рестарта воркера пайплайн продолжает с последнего корректного шага — экран показывает это явно («Продолжено с шага 3 после перезапуска»); завершённые шаги не перезапускаются |

## 5. Отчёт (по одной ссылке)

Резюме + решение, рынок, аудитории + гипотезы, эффективность + прогноз, риски, эксперименты, MVP, источники, история.

| Состояние | Поведение |
|---|---|
| Начало | Секции отчёта по порядку; навигация по якорям; метка версии отчёта |
| Успех | Полный отчёт: резюме, рекомендация (develop/validate_first/postpone/reject/insufficient_data) чипом, балл, стоп-факторы |
| Пусто | Отчёт без данных (анализ не завершён): «Отчёт будет доступен после завершения анализа» + ссылка на ход работы |
| Ожидание | Частичный отчёт: готовые секции показаны, неготовые — skeleton + «Секция формируется…» |
| Ошибка | Не удалось загрузить отчёт: баннер + «Повторить»; битый ответ модели не попадает в отчёт молча — секция помечена «Секция не удалось собрать, см. журнал» |
| Восстановление | После изменения идеи старый отчёт остаётся доступным по ссылке (история версий), сверху плашка «Данные частично устарели, актуальная версия: N» |

Доказательность: каждый факт — URL + источник + дата; факты/оценки/прогнозы/симуляции/синтетика различимы метками (`fact` / `estimate` / `forecast` / `simulation` / `synthetic`).

## 6. Прогоны и эффективность

Исходный процесс, сравнение вариантов, наборы данных, журнал вызовов, метрики качества, формулы, стат. интервалы, сценарии, график чувствительности.

| Состояние | Поведение |
|---|---|
| Начало | Выбор идеи → сводка: исходный процесс vs варианты; таблицы сравнения |
| Успех | Прогон завершён: метрики (время, доля корректных), формулы мат. модели видны, CI/bootstrap с seed, 3 сценария, график чувствительности |
| Пусто | Прогонов нет: «Запустите прогон, чтобы сравнить варианты» + CTA |
| Ожидание | Прогон идёт: статус «Выполняется вариант B, обращение 47 из 200…»; журнал вызовов пополняется |
| Ошибка | Сбой прогона: частичный протокол сохраняется, ошибки в журнале вызовов видны; «Повторить прогон»; FIXTURE-прогоны помечены явно |
| Восстановление | Повторный прогон с теми же параметрами и seed → идентичный результат (воспроизводимость — проверяемый тест); журналы старых прогонов остаются |

Вырожденные данные: нулевая база / пропуски / малая выборка / отрицательный эффект → расчёт возвращает явное предупреждение и не показывает выдуманные цифры.

## 7. Настройки и документация

Управляемые параметры анализа, лимиты, документация для проверки.

| Состояние | Поведение |
|---|---|
| Начало | Секции: параметры ролей/промптов (read-only просмотр + правка владельцем), лимиты, версии конфига |
| Успех | Изменение критерия/критерия оценки/лимита → сохранение, новая версия конфига, чип «Сохранено» |
| Пусто | Раздел документации всегда непустой (статические страницы) |
| Ожидание | Сохранение конфига — спиннер на кнопке |
| Ошибка | Невалидное значение лимита: красная рамка + текст ошибки; сохранение не удалось — баннер |
| Восстановление | Отмена правки возвращает сохранённые значения; история версий конфига доступна |

Раздел «Документация»: контекст и границы, требования с критериями приёмки, архитектура, интеграции с поведением при отказе, модели эффективности, запуск/поддержка, что развивать дальше, доказательства (тест-матрица, DEVLOG, исходники).
